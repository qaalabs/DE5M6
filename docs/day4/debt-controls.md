# From Technical Debt to Governance Controls

Bridges the Technical Debt Audit into the Deployment Governance discussion.

Look back at the issues each group reported. For each one: would a deployment pipeline or governance process have caught this automatically, or does it need a person to catch it?

## Discussion

- Which of today's issues could an automated pipeline check have blocked before it reached production? *(e.g. hard-coded credentials, missing config, outdated dependencies)*
- Which ones need a person to judge, not just a rule? *(e.g. poor naming, missing comments, incomplete docs)*
- How could this have been prevented in the first place?
- What processes would help catch these earlier?
